# Лабораторная работа №8. Работа с базой данных

## 1. Цель работы
Освоить работу с реляционными базами данных в PHP с использованием PDO. Перенести хранение данных из файлов в базу данных, реализовать полный цикл операций CRUD: создание, чтение, обновление и удаление записей.

## 2. Выполнение работы
В рамках лабораторной работы проект «Movie Tracker» был мигрирован с файлового хранения (JSON) на реляционную СУБД MySQL. Реализовано следующее:

- **Проектирование схемы БД:** Созданы две таблицы `genres` (справочник) и `movies` (основные данные) со связью «один ко многим» (`movies.genre_id` → `genres.id`). Добавлены индексы для оптимизации сортировки и поиска.
- **Подключение к БД:** Реализован класс `Database` (шаблон Singleton) для инкапсуляции PDO-подключения. Параметры вынесены в `includes/config.php` с поддержкой переменных окружения.
- **CRUD-операции:** В `includes/functions.php` написаны функции:
  - `createMovie()` — добавление записи с возвратом нового ID;
  - `getAllMovies()` — выборка всех записей с сортировкой на уровне SQL;
  - `getMovieById()` — получение одной записи по идентификатору;
  - `updateMovie()` — обновление существующей записи;
  - `deleteMovie()` — безопасное удаление записи;
  - `searchMovies()` - поиск по названию и описанию.
- **Безопасность:** Все SQL-запросы выполняются исключительно через подготовленные выражения (`prepare()` + `execute()`). Реализована защита форм от CSRF-атак через генерацию, валидацию и ротацию токенов в сессии.
- **Интерфейс:** Обновлены нативные PHP-шаблоны и Twig-версии. Добавлены страницы редактирования (`edit.php`) и удаления (`delete.php` с методом POST). Формы адаптированы под новую структуру (текстовый жанр заменён на `genre_id`).
- **Обработка ошибок:** Добавлены проверки на валидность ID, существование записей и результаты выполнения SQL. Исключения PDO обрабатываются через `try-catch` с выводом понятных сообщений пользователю.

## 3. Ответы на контрольные вопросы

### Что такое PDO и чем он отличается от устаревших расширений `mysqli_*`?
**PDO (PHP Data Objects)** — это универсальный объектный интерфейс для работы с различными СУБД (MySQL, PostgreSQL, SQLite, Oracle и др.) через единый API.
**Ключевые отличия от `mysqli_*`:**
- **Кроссплатформенность:** PDO позволяет менять СУБД без переписывания кода, тогда как `mysqli` работает исключительно с MySQL.
- **Параметризация:** PDO поддерживает именованные параметры (`:param`), что делает сложные запросы читаемее. `mysqli` использует только позиционные (`?`).
- **Архитектура:** PDO спроектирован полностью в ООП-стиле. `mysqli` имеет смешанный процедурный и объектный API, что может приводить к несогласованности кода.
- **Обработка ошибок:** PDO по умолчанию использует исключения (`PDO::ERRMODE_EXCEPTION`), что упрощает контроль потока выполнения и отладку.

### Что такое подготовленные выражения и зачем они нужны? Как они защищают от SQL-инъекций?
**Подготовленные выражения (Prepared Statements)** — это механизм, при котором структура SQL-запроса отправляется на сервер и компилируется отдельно от передаваемых данных.
**Принцип защиты от SQL-инъекций:**
1. Сервер сначала **парсит шаблон** запроса (например, `SELECT * FROM movies WHERE id = :id`). На этом этапе фиксируется логика выполнения.
2. Данные привязываются к параметрам через `execute()`. СУБД обрабатывает их строго как **скалярные значения**, а не как исполняемый SQL-код.
3. Поскольку структура запроса уже зафиксирована, любые специальные символы (`'`, `;`, `--`, `DROP TABLE`) экранируются автоматически и не могут изменить логику выполнения запроса.

### Что такое транзакция в базе данных? В каких ситуациях её стоит использовать?
**Транзакция** — это группа операций с БД, которая выполняется как единое атомарное целое. Транзакция подчиняется свойствам ACID (Атомарность, Согласованность, Изолированность, Долговечность).
**Ситуации для использования:**
- Когда несколько запросов должны либо **все выполниться успешно**, либо **все отмениться** при ошибке (например, перевод средств между счетами: списание у одного и зачисление другому).
- При каскадном удалении или обновлении связанных записей, где важно гарантировать целостность данных даже при сетевом сбое или исключении в коде.
- При массовых операциях (`INSERT`/`UPDATE` сотен записей) для повышения производительности (один коммит вместо сотен).

### Чем отличается `fetch()` от `fetchAll()` в PDO?
- **`fetch()`** — возвращает **одну строку** результата за каждый вызов и перемещает внутренний указатель на следующую запись. Эффективен по памяти при работе с большими выборками, так как не загружает весь результат в RAM сразу.
- **`fetchAll()`** — возвращает **все строки** результата в виде двумерного массива за один вызов. Удобно для небольших выборок и прямой передачи данных в шаблоны, но потребляет значительно больше памяти и может замедлить работу при тысячах записей.
