# Отчёт по лабораторной работе

## 1. Цель
Освоить шаблонизацию в PHP двумя способами:
- нативные PHP-шаблоны,
- готовый шаблонизатор Twig.

Улучшить структуру проекта, разделив логику обработки данных и отображение.

## 2. Структура проекта
Проект реализован с разделением на два уровня:

- `index.php`, `list.php`, `save.php` — логика маршрутизации и обработки.
- `includes/functions.php` — функции для загрузки/сохранения данных, рендеринга шаблонов и валидации.
- `templates/` — нативные PHP-шаблоны:
  - `layout.php`
  - `form.php`
  - `list.php`
  - `errors.php`
  - `success.php`
- `twig/` — аналогичная версия на Twig:
  - `index.php`
  - `list.php`
  - `save.php`
  - `templates/`
    - `layout.html.twig`
    - `form.html.twig`
    - `list.html.twig`
    - `errors.html.twig`
    - `success.html.twig`
- `data/data.json` — файл данных в JSON-формате.

## 3. Реализация нативных PHP-шаблонов
В `includes/functions.php` реализована функция `render()`, которая:
- принимает имя шаблона и параметры,
- подготавливает переменные через `extract()`,
- рендерит содержимое шаблона,
- оборачивает результат в общий `layout.php`.

Шаблоны в `templates/` содержат только HTML и вывод данных:
- форма добавления записи;
- таблица списка;
- вывод ошибок;
- страница успешного сохранения.

Логика в `list.php` и `save.php` отделена от представления:
- загрузка данных,
- сортировка,
- валидация,
- добавление записи.

## 4. Реализация Twig
Добавлен `composer.json` с зависимостью `twig/twig`.

Создан `includes/twig.php`, который:
- инициализирует `Twig\Environment`,
- подключает шаблоны из директории `twig/templates`,
- регистрирует собственный фильтр `status_icon`.

Внутренняя логика в `twig/` осталась близка к нативной версии, но шаблоны написаны на Twig:
- `layout.html.twig` задаёт общий макет;
- дочерние шаблоны используют `{% extends 'layout.html.twig' %}` и `{% block content %}`.

Дополнено:
- на странице списка выводится эмодзи статуса через Twig-фильтр `status_icon`.

## 5. Дополнительная функция
Реализован собственный Twig-фильтр `status_icon`, который заменяет статус записи на эмодзи:
- `Смотрю` → `👀`
- `Хочу посмотреть` → `📌`
- `Просмотрено` → `✔️`

Это решение соответствует дополнительному заданию для 10 баллов.

## 6. Ответы на контрольные вопросы
### В чём отличие нативных PHP-шаблонов от Twig?
- Нативные шаблоны — это обычный PHP-код, выполняемый как HTML.
- Twig — шаблонизатор с собственным синтаксисом и ограниченной логикой.
- Twig делает шаблоны более безопасными и читаемыми, снижает риск смешивания бизнес-логики и представления.

### Преимущества и недостатки
**Нативные шаблоны:**
- + легко писать, не требуется сторонняя библиотека;
- + быстрее для простых проектов;
- - легко смешать логику и представление.

**Twig:**
- + чёткое разделение слоёв, шаблоны безопаснее;
- + поддержка наследования, блоков, фильтров;
- - требуется установка зависимости, немного выше порог изучения.

### Зачем разделять логику и представление?
- Чтобы код был структурированным, проще поддерживался и тестировался.
- Если смешивать их в одном файле, появляются:
  - дублирование,
  - сложность поддержки,
  - повышенный риск ошибок,
  - плохая читаемость.

### Что такое наследование шаблонов в Twig?
- `{% extends %}` позволяет базовому шаблону задавать общий каркас.
- `{% block %}` обозначает участки, которые дочерний шаблон может переопределить.
- Это позволяет держать общий макет отдельно и изменять только содержимое конкретных страниц.

## 7. Итог
Проект содержит оба варианта:
- нативный PHP-шаблоны для сравнения;
- Twig-версию с наследованием шаблонов и собственным фильтром.
